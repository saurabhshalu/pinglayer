# PingLayer Frontend Implementation Specification

**For the Gemini Frontend Agent**

## Technology Stack

- **Bundler:** Vite
- **UI:** React 18+
- **Styling:** Tailwind CSS
- **State:** `useState`, `useEffect`, `useMemo`, `useCallback`, React Context where needed
- **No** Redux, Zustand, MobX, Recoil, or Jotai

---

## Base URL

All API calls go to:
```
VITE_API_BASE_URL (env variable)
```

Example: `https://pinglayer.yourcompany.com`

---

## Authentication Architecture

There are **two separate authentication contexts**:

### 1. Admin UI
- Header: `Authorization: Bearer <ADMIN_AUTH_SECRET>`
- Store token in `localStorage` under `pinglayer_admin_token`
- The admin can manage products, generate API keys, view all data

### 2. Product API User (SaaS product context)
- Header: `Authorization: Bearer <product_api_key>`
- Store in `localStorage` under `pinglayer_api_key`
- The product user manages their own connections, definitions, mappings, and views their notifications

Both UIs can be in the same React app with different route guards.

---

## API Service Layer

Create a `src/services/api.ts` module:

```ts
const BASE = import.meta.env.VITE_API_BASE_URL;

async function request<T>(path: string, opts: RequestInit, token: string): Promise<T> {
  const res = await fetch(`${BASE}${path}`, {
    ...opts,
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${token}`,
      ...opts.headers,
    },
  });
  const body = await res.json();
  if (!res.ok) throw body; // { success: false, error: { code, message } }
  return body.data ?? body;
}
```

Group API calls by domain: `src/services/products.api.ts`, `src/services/connections.api.ts`, etc.

## Routing

Use React Router v6.

```
/                     → redirect to /admin/products (if admin) or /connections (if product user)
/login                → Admin login
/api-login            → Product API key login

/admin/products       → Admin: Products list
/admin/products/:id   → Admin: Product detail (API keys)
/admin/connections    → Admin: All connections
/admin/notifications  → Admin: All notifications

/connections          → Product: My connections
/connections/new      → Product: Create connection
/connections/:id      → Product: Connection detail

/definitions          → Product: Notification definitions
/definitions/new      → Product: Create definition
/definitions/:id      → Product: Definition detail + mappings

/notifications        → Product: Notification history
/notifications/:id    → Product: Notification detail

/settings             → Product: API key display
```

### Page 8: Create / Edit Connection (`/connections/new` and `/connections/:id`)

| Field | Type | Validation |
|-------|------|------------|
| Tenant ID | text | required, max 255 |
| Channel | select | whatsapp / email / sms |
| Provider | select | (filtered by channel) |
| Auth Method | select | manual / embedded_signup |

**WhatsApp / Meta specific credential fields** (shown when channel=whatsapp, provider=meta):

| Field | Input type | Notes |
|-------|------------|-------|
| WhatsApp Business Account ID (WABA ID) | text | required |
| Phone Number ID | text | required |
| Access Token | `type="password"` with show/hide toggle | required |

**CRITICAL UI requirements for Access Token:**
- Render as `<input type="password">` by default
- Show/hide toggle (eye icon) to reveal
- On edit form (existing connection): show placeholder `••••••••` — **never** fetch or display the stored token
- Show-then-hide: if user clicks show, they see the token they just typed. After save, show blank/placeholder again.
- Do NOT pre-fill the access token field from the API response (the API never returns it)
- Include helper text: "Your access token is encrypted and stored securely. Leave blank to keep existing token."

**"Test Connection" button** (on edit form):
- Calls `POST /api/v1/connections/:id/validate`
- Shows result: ✓ Connected (with phone number, display name) or ✗ Error

**Status update** (on edit form):
- Toggle: Active / Inactive

**Save:**
- Loading state on button
- Success toast: "Connection saved"

## Shared Components

### `StatusBadge`
Props: `status: string`, `type: 'connection' | 'notification' | 'product' | 'apikey'`

Color map:
```
connection: active=green, inactive=gray, invalid=red, pending=yellow
notification: queued=yellow, processing=yellow, sent=blue, delivered=teal, read=green, failed=red
product: active=green, inactive=gray, suspended=red
apikey: active=green, revoked=red
```

### `ApiKeyDisplay`
Used when showing a newly generated key. Props: `apiKey: string`

- Monospace display
- Copy to clipboard button (shows checkmark for 2s after copy)
- Warning banner: "This key will not be shown again"
- Blurred by default with "Click to reveal" button

### `PasswordInput`
Props: `value`, `onChange`, `placeholder`, `label`

- `<input type="password">` with eye icon toggle
- On show: switches to `type="text"`

### `ConfirmDialog`
Props: `title`, `message`, `onConfirm`, `onCancel`, `danger?: boolean`

- Modal dialog
- Cancel (ghost) + Confirm (red if `danger`) buttons

### `Toast`
Global toast notifications: success (green), error (red), info (blue).

Use a simple React Context + portal approach.

### `Pagination`
Props: `page`, `totalPages`, `onPageChange`

Standard ← Prev [1] [2] [3] Next → controls.

### `EmptyState`
Props: `title`, `description`, `action?: { label, onClick }`

Centered empty state with optional CTA button.

### `JsonViewer`
Collapsible pre-formatted JSON. Used for provider responses.

## Form Validation

Client-side validation using React state (no library needed):

- Required fields: show red border + error message on blur
- Slug: validate `^[a-z0-9-]+$`
- Definition key: validate `^[A-Z_]+$`
- Phone: validate `^\d{7,15}$`
- Show validation errors inline (below field)
- Disable submit button while loading

---

## Loading States

Every data-fetching component should show:
- Skeleton loaders (gray bars) while loading — NOT a full-page spinner
- Error state with retry button on fetch failure
- Loading spinner on action buttons (submit, test, validate)

---

## Error Handling

Parse the standard error shape:
```json
{ "success": false, "error": { "code": "...", "message": "..." } }
```

- HTTP 401 → clear stored token, redirect to `/login` or `/api-login`
- HTTP 422 → show validation errors inline
- HTTP 409 → show "already exists" message
- HTTP 5xx → show "Server error, please try again"

## Security UI Requirements

1. **Never display stored access tokens** in edit forms. Pre-fill with empty string.
2. **Show new API keys with a warning** and blur by default.
3. **Credentials fields** are always `type="password"` until user toggles show.
4. **Copy buttons** should not persist the key in the DOM after copy.
5. **Logout** clears `localStorage` tokens.

## Sample API Flow: Complete Setup Walkthrough

This describes the user journey through the UI:

1. Admin logs in → `/login`
2. Admin creates product "Inventory SaaS" → `/admin/products`
3. Admin generates API key → shows modal with raw key
4. Product user logs in with API key → `/api-login`
5. Product user creates connection:
   - Tenant ID: `merchant-123`
   - Channel: `whatsapp`, Provider: `meta`
   - Auth: manual — fills WABA ID, Phone Number ID, Access Token
   - Clicks "Validate" → sees "✓ Connected: +91 98765 43210 · Test Business"
   - Saves → status becomes `active`
6. Product user creates notification definition: `ORDER_SHIPPED`
7. Product user creates template mapping:
   - Connection: merchant-123's WhatsApp
   - Template name: `order_shipped`
   - Language: `en_US`
   - Variable mapping: `1 → customerName`, `2 → orderId`, `3 → trackingNumber`
8. SaaS backend calls `POST /api/v1/notifications/send`
9. Product user views notification history — sees the sent notification

## Additional Notes for the Gemini Agent

- **TypeScript** — use it for all files (`.tsx`/`.ts`)
- **Vite** — configure `VITE_API_BASE_URL` in `vite.config.ts` proxy for local dev
- **No date library needed** — use `Intl.DateTimeFormat` for formatting
- The API returns `created_at` / `updated_at` as ISO strings
- Pagination response shape: `{ data: [], pagination: { page, limit, total, totalPages, hasNext, hasPrev } }`
- All error responses: `{ success: false, error: { code, message, details? } }`
- The `channel` values are: `whatsapp`, `email`, `sms`, `push`
- The `provider` values are: `meta`, `twilio`, `sendgrid`, `smtp`, `fcm`
- For now, only `whatsapp + meta` is functional — gray out other options or add "(coming soon)" label
